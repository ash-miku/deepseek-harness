# Agent Note: 折叠聊天中保持插话顺序

Status: implemented

[English](2026-08-19-chat-fold-interjection-order.md) | 中文

## 问题

Web 聊天按整个 turn 折叠思考、工具调用和模型回答。运行中的 turn 可能在两个模型步骤之间接收用户插话，因此整回合分组会把后续回答渲染到插话之前，尽管持久事件顺序已经把插话排在前面。

## 决策

折叠组改为在一个 turn 内按连续的过程节点和回答节点构建。用户、插话、上下文或其他非过程可见节点都会结束当前片段；后续模型步骤从新的折叠组开始。每个片段内部继续使用现有的过程折叠和回答渲染，片段之间则遵循 Chat 顺序作为对话顺序来源。

## 备选方案

**保留整回合分组。** 它能让每个 turn 只有一个紧凑的过程折叠，但会把后续回答跨过插话和上下文行，导致对话顺序失真。

**插话后关闭过程折叠。** 它能保持行顺序，却会移除该 turn 的默认折叠；按片段分组同时保留顺序和折叠偏好。

**重排持久 Chat 节点。** 这会让展示层修复事件派生顺序，并可能影响回放、位置索引和其他渲染器；缺陷属于展示分组算法。

## 影响

当输入或上下文行分隔多个工具或思考阶段时，一个 turn 可能显示多个过程折叠。每个折叠仍只包含它所拥有的连续思考、工具和回答节点，插话后的回答在完整、折叠和回放视图中都会显示在插话下方。

ChatView 聚焦测试覆盖折叠模式开启时旧回答、插话和后续回答的 DOM 顺序。
