# Agent Note: Web 会话与项目基线在启动瞬态失败后重试

Status: implemented

[English](2026-08-20-web-baseline-startup-retry.md) | 中文

## 问题

Web 客户端在每个连接代次就绪时各执行一次会话列表和项目列表拉取。DSH 启动期间 Host 短暂失败后，相应列表会保持在带错误的 `pending` 阶段且不再发起请求，页面因此显示空项目，直到重启服务建立新的连接代次。

## 决定

客户端运行时会在当前连接仍然有效且对应基线尚未成功时，重试失败的 `session.list` 或 `workspace.list`。重试共用指数退避，从 250 毫秒开始，最大间隔 5 秒。基线成功后退避归零，新连接开始新的重试序列，断线或运行时销毁会取消未执行的定时器。成功返回空列表仍会把阶段推进到 `ready`；真实的空部署不会被客户端持续轮询。

会话管理器和项目管理器分别拥有自己的重试定时器，因为它们分别拥有两条独立的基线生命周期。`WorkspaceRuntime` 将连接销毁转发给项目管理器，运行时在停止连接流前销毁两个管理器的重试状态。

## 备选方案

**让 systemd 单元延迟更久再启动 DSH。** 否决：失败发生在 Web 服务已经监听后仍可能发生的 RPC 基线请求启动竞态中，单纯延迟服务无法覆盖后续连接代次或存储恢复。

**只重试 `session.list`。** 否决：初始项目选择要求会话和项目两条基线都成功，项目列表失败同样会产生空项目。

**把成功的空列表当成瞬态失败。** 否决：空列表是合法的持久化状态；如果不改变 wire contract，客户端无法区分“后端已就绪但没有会话”和“后端尚未就绪”。

## 后果

当 Host 在 Web 连接建立后短暂恢复时，首次页面加载可以自行显示历史会话和项目，不再需要手动重启服务。Host 持续不可用时，客户端会以有上限的间隔持续重试，直到连接代次结束；普通重连会取消旧定时器并开始新的序列。重试等待期间列表状态仍保留最近一次错误，成功响应继续沿用原有的增量变更回放和排序逻辑。

## 测试

`packages/client/runtime/tests/manager.client.spec.ts` 和 `packages/client/runtime/tests/workspaces-service.client.spec.ts` 覆盖首次连接拉取失败、延迟重试成功、阶段恢复和定时器清理。运行时聚焦测试、仓库类型检查和空白检查均通过。
