# Agent Note: 限制 Git 变更状态响应

Status: implemented

[English](2026-09-14-git-changes-response-cap.md) | 中文
## 问题

Changes 标签页先执行 `git status --untracked-files=all`，再为每个未跟踪路径单独启动一个 `git diff --no-index` 进程以获取该路径的行数。当工作区存在规模很大的未跟踪目录（如 node_modules）时，会产生无上限的路径列表和逐路径进程，导致标签页需要数分钟才能打开，并返回超大响应。

## 决策

status 路由最多返回 100 个改动路径。它先对所有路径排序，在填充上限时让已跟踪改动优先于未跟踪改动，并且只为实际返回的路径执行未跟踪路径的 numstat。响应携带截断前的 `total` 与 `truncated` 标记；Changes 视图显示真实总数并提示已截断，输入区统计以 `total` 计数，行数总量只汇总返回的路径。

## 考虑过的替代方案

**客户端分页（“加载更多”）。** 这需要 offset 参数、客户端追加状态和第二套拉取契约，而该问题的核心只是避免标签页卡死；返回有界的第一页并明确提示即可满足同一需求。

**保留完整列表，只限制逐文件 numstat 循环。** 列表和 JSON 响应仍然无上限，大目录依旧会流式传输并渲染数千行。

**提高上限但不优先保留已跟踪改动。** 未跟踪路径会与已跟踪路径混排（`node_modules` 排在 `src` 之前），按路径截断会把真实改动藏在未跟踪噪声之后。

## 影响

改动路径超过 100 个工作区不再会卡住标签页，真实改动保持可见。超出上限的路径不会列出，未跟踪行数只为返回的路径计算，因此当未跟踪目录被大量截断时，输入区的行数总量会偏小，而文件计数保持精确。基于真实仓库的定向路由测试覆盖了已跟踪优先的上限逻辑与 `total`/`truncated`；客户端测试覆盖了提示。
