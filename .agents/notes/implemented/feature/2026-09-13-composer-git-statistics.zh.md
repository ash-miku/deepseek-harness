# Agent Note: 输入框底部 Git 统计

Status: implemented

[English](2026-09-13-composer-git-statistics.md) | 中文
## 问题

输入框底部展示会话用量，但用户必须打开变更页才能查看未提交工作区的规模。分支对比统计回答的是另一个问题。

## 决策

点击统计会通过外壳共享的视图选择动作切换到当前会话的变更页。聊天模块拥有可追加的统计插槽；Git 变更插件通过该插槽提供本地化文件数和行数。现有鉴权状态接口提供工作区统计，不受变更页选择的分支影响。新文本文件使用 Git numstat 统计，包括末尾没有换行的文件；二进制文件只计入文件总数。首次提交之前，已跟踪文件与空树比较。

## 考虑过的替代方案

**在聊天模块中导入 Git 组件。** 这会将通用会话界面与可选功能耦合，并违反功能包之间的运行时隔离规则。

**复用所选分支的统计。** 这些数据包含已提交改动，不能描述未提交工作。

**持续轮询。** 按会话状态和窗口焦点刷新，既能提供有用统计，也避免持续扫描空闲工作区。

## 影响

底部保留原有用量控件，并复用变更页颜色。外部文件系统改动在下次窗口获得焦点或会话状态变化时显示。每个未跟踪文件需要一次限制输出大小的 Git 调用。定向客户端测试和真实仓库路由测试覆盖统计、刷新、取消及仓库不可用场景；该功能不改变模型请求或会话日志。
